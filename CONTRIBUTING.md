# Contributing / Mitwirken

[English](#english) | [Deutsch](#deutsch)

## English

Contributions are welcome. This is a source-available, noncommercial project
under the custom [PlaylistResume Noncommercial License](LICENSE).

### Propose a change

1. Open an issue for a bug or discuss a larger feature before implementing it.
2. Fork the repository, make a focused change on a branch, and open a pull request.
3. Explain the behavior before and after the change and how you verified it.
4. Run checks relevant to your change; see [Testing](docs/TESTING.md).

The maintainer decides which changes enter the official project. Pull requests
do not require direct write access to the repository. Independent commercial
use and standalone distributions are not granted by the project license.

### Rights in contributions

Only submit code you are entitled to contribute. By intentionally submitting a
contribution for inclusion, you grant the project maintainer the rights in
section 6 of LICENSE to maintain, modify, and distribute it within the official
noncommercial project. You retain rights in your contribution. Commercial
relicensing requires a separate agreement; submitting a pull request does not
transfer your copyright to the maintainer.

Identify any third-party material and its license. Do not submit original or
patched Wallpaper Engine executables, complete UI bundles, user configurations,
position files, backups, credentials, or other people's private logs.

### Compatibility and checks

The published runtime targets the exact pinned Wallpaper Engine 2.8.42 Steam
files. An engine update needs separate analysis, hash verification, and tests;
do not bypass the checks for unknown files. Preserve upgrade, rollback, profile,
manual-selection, and multiple-monitor behavior when changing the runtime.
Development and build instructions are in [Build](docs/BUILD.md).

## Deutsch

Beiträge sind willkommen. Das Projekt verwendet die individuelle,
nichtkommerzielle [PlaylistResume-Lizenz](LICENSE). Der englische Lizenztext
ist maßgeblich.

1. Fehler als Issue melden; größere Funktionen vorher besprechen.
2. Einen Fork mit eigenem Branch anlegen und einen Pull Request erstellen.
3. Änderung, erwartetes Verhalten und passende Prüfungen beschreiben.
4. Relevante Tests aus [Testing](docs/TESTING.md) ausführen.

Du brauchst dafür keine direkten Schreibrechte. Über die Übernahme in das
offizielle Projekt entscheidet der Maintainer.

Mit einem bewusst zur Aufnahme eingereichten Beitrag räumst du die in Abschnitt
6 der LICENSE beschriebenen Nutzungsrechte für das offizielle nichtkommerzielle
Projekt ein. Deine Rechte an deinem Beitrag bleiben erhalten. Eine kommerzielle
Umlizenzierung benoetigt eine separate Vereinbarung.

Nur Material einreichen, an dem du die erforderlichen Rechte hast. Fremde
Lizenzen angeben. Keine vollständigen Wallpaper-Engine-Programmdateien,
Benutzerkonfigurationen, Positionsspeicher, Backups oder privaten Daten hochladen.
